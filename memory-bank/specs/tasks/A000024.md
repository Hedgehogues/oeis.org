# A000024 — positive integers ≤ 2ⁿ of the form x² + 10y²

## Vision
`a(n)` counts the distinct positive integers up to `2ⁿ` expressible as `x²+10y²`. This is the exact
same construction as `A000018` (`x²+16y²`) with `D=10` in place of `D=16` — the same collision
mechanism (different `(x,y)` pairs landing on the same value), the same reason naively counting
`(x,y)` pairs would overcount, drawn once on `A000018`'s page rather than redrawn here.

## Terms
MUST/MUST NOT/SHALL/SHOULD/SHOULD NOT/MAY as in RFC 2119. Uses two catalogued devices, both reused
unchanged and both rendered by `A000018`'s page:
[device::RepresentationGrid](../../_terms.md#devicerepresentationgrid),
[device::LogGrowthChart](../../_terms.md#deviceloggrowthchart).

## Scope
**In scope:** the `solution.mjs`/`proof.mjs` pair for A000024, and this entry's deliberate
borrowing of `memory-bank/visualizations/A000018/viz.html`.

**Out of scope:** a page, screenshots or device records of this sequence's own — a thin entry by

in `memory-bank/specs/tasks/A000018.md`.

## Architecture

### Overview (prose)
This sequence has no page. It borrows `memory-bank/visualizations/A000018/viz.html`, whose 5×5
representation grid and growth chart apply unchanged with `D=10` substituted for `D=16` — the same
collision mechanism, the same reason deduplication is the real work, the same log-scaled growth.

### Code
`sequences/A000024/solution.mjs` sieves every value `x²+10y² ≤ bound` into a flat byte array and
counts first-time marks — `A000018/solution.mjs`'s method with `16` replaced by `10`.
`sequences/A000024/proof.mjs` shares no code with it: for every candidate value from 1 to the bound,
it independently tests membership by looping over `y` and checking whether `v−10y²` is a perfect
square.
