# A000029 — bracelets: necklaces with turning over allowed

## Vision
`a(n)` counts binary necklaces of `n` beads up to BOTH rotation and reflection ("bracelets"). The
naive question ("how many colorings?") gives `2^n`, which massively overcounts since most colorings
are rotations or reflections of each other. The page's central claim: rather than searching for and
deduplicating orbits, the exact orbit count is the plain arithmetic MEAN of how many strings each of
the group's `2n` symmetry moves leaves completely unchanged — Burnside's lemma, made checkable by
printing every move's own fixed-string count rather than asserting the mean.

## Architecture

### Overview (prose)
`memory-bank/visualizations/A000029/viz.html` runs Problem (4 six-bead strings, "how many
bracelets, really?") → (1: one string rotated then reflected, same bracelet both times) → (2:
Burnside's lemma, via [device::BurnsideFixedPointTable](../../_terms.md#deviceburnsidefixedpointtable)
— all 12 elements of the dihedral group for `n=6`, each chip's own fixed-string count, averaging to
13) → Solution (the Problem's 4 strings collapse to 2 bracelets, via
[device::MergedResultStrip](../../_terms.md#devicemergedresultstrip) merging the 3 that share an
orbit into one block while the 4th stays separate, beside the count and a verified-match badge).

### Code
`sequences/A000029/solution.mjs` computes `a(n)` by exactly the procedure the page draws: flood-fill
every unvisited string's orbit under rotation and reflection over the full `2^n`-string state space,
counting one orbit per fill. `sequences/A000029/proof.mjs` does not reuse that search: it
independently verifies every orbit is genuinely closed under both moves and that the orbits
partition the whole state space (soundness), then re-derives the count via Burnside's lemma —
building each of the dihedral group's `2n` elements as an explicit position permutation, decomposing
each into cycles from scratch, and averaging `2^cycles` over all elements — before comparing the
final counts to OEIS's published terms.
