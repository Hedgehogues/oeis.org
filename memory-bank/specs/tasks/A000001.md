# A000001 — Number of groups of order n

## Vision
`a(n)` counts the non-isomorphic groups of order `n`. The naive question ("how many groups of size
n") gives no handle on WHY the count jumps the way it does (1 for every prime, an explosion for
powers of two). The page's central claim: a symmetry's possible "repeat lengths" (how many times a
movement must repeat before undoing itself) are exactly the divisors of `n` — everything else
follows from combining movements with those allowed lengths, and the size of the divisor set is
what decides whether the count stays small or explodes.

## Architecture

### Overview (prose)
`memory-bank/visualizations/A000001/viz.html` runs Problem → (1: what a "type of symmetry" even is, via
[device::MarkedAsymmetry](../../_terms.md#devicemarkedasymmetry),
[device::CayleyTable](../../_terms.md#devicecayleytable),
[device::SelfCancelDiagonal](../../_terms.md#deviceselfcanceldiagonal) and
[device::StateMap](../../_terms.md#devicestatemap), the last contrasting a whole extra object
against the rectangle within the same card) → (2: which repeat-lengths are possible for a given
`n`, via [device::OrbitRing](../../_terms.md#deviceorbitring), trying every length from 1 to `n`
directly) → (3: how repeat-lengths combine for `n=6`, via
[device::CombinationFork](../../_terms.md#devicecombinationfork)) → (4: why the count jumps for
larger `n`, via [device::DivisorChips](../../_terms.md#devicedivisorchips) and
[device::CombinationFork](../../_terms.md#devicecombinationfork) reused for the order-8 recipes) →
Solution (a catalog of shapes for `n=1..15`, a
[device::LogGrowthChart](../../_terms.md#deviceloggrowthchart) of counted tiles for `n=16..30`, and
[device::UnrealizedPlaceholder](../../_terms.md#deviceunrealizedplaceholder) for the one order-8
type with no realizable object), tied together with
[device::MiniRecap](../../_terms.md#deviceminirecap) thumbnails in a closing "how the answers
combine" map.

### Code
`sequences/A000001/solution.mjs` computes `a(n)` by exactly the procedure the page draws: fix the
identity at element 0, fill the rest of the `n×n` multiplication table by backtracking under the
Latin-square and partial-associativity constraints, then merge tables that differ only by
relabelling. `sequences/A000001/proof.mjs` takes that output and refuses to trust it — it revalidates
each table as a group, re-tests distinctness with a from-scratch permutation search that shares no
pruning with the one used to produce the answer, matches every returned table against a group built
by a named construction (cyclic, direct products, dihedral, quaternion), and only then compares the
counts to OEIS.

### Data
- `memory-bank/visualizations/A000001/viz.html` embeds `a(1)..a(30)`.
- `memory-bank/visualizations/A000001/drafts/v1-heatmap.html` embeds `a(1)..a(64)` and renders full Cayley tables
  for the 5 groups of order 8 (`C8`, `C4×C2`, `C2³`, `D8`, `Q8`).
- `memory-bank/visualizations/A000001/drafts/v2-symmetry-catalog.html` uses the divisor/Sylow argument for `n=p·q`
  and the asymptotic formula for `a(2^k)` — no group tables of its own beyond what the first draft
  already covers.
