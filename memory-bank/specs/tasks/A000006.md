# A000006 — integer part of the square root of the n-th prime

## Vision
`a(n) = ⌊√prime(n)⌋`. The per-term formula is a one-line restatement of the definition and carries
no picture on its own. What DOES carry a picture: because the sequence is monotone non-decreasing,
it decomposes into runs of a repeated value `k`, and run `k`'s length is exactly the number of
primes in `(k², (k+1)²]`. The page's central claim: whether that length can ever be zero — i.e.
whether some pair of consecutive squares has no prime between them — is Legendre's conjecture, open
since 1808. The page checks this claim over the range it can reach and states plainly that checking
is not proving.

## Terms
MUST/MUST NOT/SHALL/SHOULD/SHOULD NOT/MAY as in RFC 2119. Uses one catalogued device, reused
unchanged: [device::RunLengthEncoding](../../_terms.md#devicerunlengthencoding).

## Scope
**In scope:** `memory-bank/visualizations/A000006/viz.html` — the current, only page for this
sequence (no kept drafts) — and the `solution.mjs`/`proof.mjs` pair.

**Out of scope:** a proof or disproof of Legendre's conjecture (open; this page checks a finite
range and says so); the broader theory of prime gaps beyond the one interval-counting argument the
page draws.

## Architecture

### Overview (prose)
`memory-bank/visualizations/A000006/viz.html` runs Problem (the first 20 terms, values repeating a
different number of times each) → (1: grouping the sequence into runs, via
[device::RunLengthEncoding](../../_terms.md#devicerunlengthencoding), with the worked example that
run `4`'s length of 3 matches the 3 primes — 17, 19, 23 — inside `(16, 25]`) → (2: could a run ever
have length zero? checked directly for `k = 1..20`, none found) → Solution (every run's length is a
prime count between consecutive squares, and Legendre's conjecture — that no such count is ever
zero — is stated as open, not resolved by this page).

### Code
`sequences/A000006/solution.mjs` sieves primes up to a bound grown until it holds enough terms, then
computes `⌊√prime(n)⌋` directly. `sequences/A000006/proof.mjs` does not reuse that sieve: it
independently tests primality by trial division, counts primes directly inside each interval
`(k², (k+1)²]`, and rebuilds the sequence by repeating `k` that many times — a reconstruction that
only reproduces `solution.mjs`'s output if every interval in range actually holds a prime, which is
exactly Legendre's conjecture restricted to the checked range, checked as a byproduct of the
independence check rather than asserted separately.
