# A000022 — centered hydrocarbons with n atoms

## Vision
`a(n)` counts unlabeled trees on `n` nodes with every vertex of degree at most 4 (a carbon
skeleton) that have exactly one Jordan center. The naive question ("how many such skeletons of size
`n`?") gives no handle on why exactly one center matters, or why some same-size skeletons are
excluded. The page's central claim: peeling any tree's leaves layer by layer — Jordan's theorem —
always stops at exactly one vertex or exactly two adjacent ones, never anything else, and this
sequence counts only the trees that stop at one; the excluded ones (A000200) stop at two, and
together the two sequences account for every quartic tree of that size (A000602).

## Terms
MUST/MUST NOT/SHALL/SHOULD/SHOULD NOT/MAY as in RFC 2119. Uses two catalogued devices, both reused
unchanged from A000014: [device::MiniRecap](../../_terms.md#deviceminirecap),
[device::LogGrowthChart](../../_terms.md#deviceloggrowthchart).

## Scope

## Architecture

### Overview (prose)
`memory-bank/visualizations/A000022/viz.html` runs Problem (two same-size, same-degree-bound
skeletons, no visible rule for telling them apart) → (1: the identical peeling rule run on both,
real intermediate states drawn frame by frame, via
[device::MiniRecap](../../_terms.md#deviceminirecap)'s own discipline — each frame a literal redraw
of the previous tree, colour-updated, not a new drawing, run twice in parallel so the same rule
visibly produces two different endings) → (2: Jordan's theorem stated — one vertex or two adjacent
ones, never anything else) → (3: the identity — centered plus bicentered accounts for every quartic
tree of that size, checked with real counts for `n=7` and cited against all three sequences' actual
published terms) → Solution (the verified growth chart through `n=20`, via
[device::LogGrowthChart](../../_terms.md#deviceloggrowthchart)).

### Code
`sequences/A000022/solution.mjs` reuses A000014's leaf-addition growth (see that sequence's own spec
for why the construction reaches every unlabeled tree with no relabelling and no combinatorial
explosion) with two changes: the degree cap (≤4) is enforced while growing rather than only at the
end, since a vertex's degree only increases on the way to `n` nodes; and the final filter keeps
trees with exactly one Jordan center rather than A000014's no-degree-2 condition.
`sequences/A000022/proof.mjs` does not reuse that construction: it independently decodes every one
of the `n^(n-2)` labeled trees on `n` nodes from its own Prüfer sequence, filters to max degree ≤4
and exactly one center with its own from-scratch centering/AHU routine, and compares the resulting
count to the fast method's output. Separately, and independently of BOTH constructions, it checks
the identity `A000022(n) + A000200(n) = A000602(n)` against all three sequences' own published
terms — a cross-check that never computes A000200 or A000602 from any construction in this
repository at all.
