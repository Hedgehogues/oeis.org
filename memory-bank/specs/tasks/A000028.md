# A000028 — numbers whose exponent 1-bits sum to an odd count

## Vision
`m` belongs to this sequence exactly when, writing `m = p_1^e_1 · p_2^e_2 · …`, the total count of
1-bits across the binary expansions of `e_1, e_2, …` is odd. The per-term rule is a one-line
restatement of factorization plus a binary-popcount parity check — no further "why" beyond the
arithmetic itself, and this page keeps its ambitions matched to that: two exact worked examples
(one marked, one not) rather than a manufactured deeper story.

## Terms
MUST/MUST NOT/SHALL/SHOULD/SHOULD NOT/MAY as in RFC 2119. Uses no catalogued device: the page's two
worked examples are plain factorization-and-binary chips, not a reusable diagram convention
distinct from what other simple pages already render without a formal `[device::*]` record.

## Scope
**In scope:** `memory-bank/visualizations/A000028/viz.html` — the current, only page for this
sequence (no kept drafts) — and the `solution.mjs`/`proof.mjs` pair.

**Out of scope:** the Lambek–Moser complementary-partition property OEIS's comments cite (this
sequence and its complement A000379 splitting the integers so that products of pairs from either
class occur with equal multiplicities) — a real, cited fact, but not one this page's picture
demonstrates; A000379 itself, which is not documented here.

## Architecture

### Overview (prose)
`memory-bank/visualizations/A000028/viz.html` runs Problem (numbers 2–17, some marked, some not) →
(1: `24 = 2³×3¹`, its exponents' 1-bit counts `2 + 1 = 3` odd, marked) → (2: `12 = 2²×3¹`, same
shape, `1 + 1 = 2` even, not marked) → Solution (the rule holds for every number checked, not only
the two worked examples).

### Code
`sequences/A000028/solution.mjs` factorizes each candidate by trial division and sums the popcount
of its exponents via a shift-and-mask loop. `sequences/A000028/proof.mjs` does not reuse either
routine: it factorizes independently through a smallest-prime-factor sieve and counts bits via
Kernighan's trick (`x &= x-1`), then checks BOTH directions directly — every returned value really
has an odd sum, and every value excluded below the same bound really has an even sum — rather than
trusting the generation loop's own logic to have been complete.
