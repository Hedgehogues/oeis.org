# A100001 — Number of self-dual combinatorial configurations of type (n_3)

## Vision
`a(n)` counts configurations of `n` points and `n` lines, each point on exactly 3 lines and each
line holding exactly 3 points, that are isomorphic to their own dual (points and lines swapped).
The page's central claim: self-duality is a claim that SOME relabeling of points and lines makes
the configuration match its dual — not that the naturally-drawn incidence matrix already equals its
own transpose — and the picture is built specifically to not overclaim the stronger, false version
of that fact.

## Terms
MUST/MUST NOT/SHALL/SHOULD/SHOULD NOT/MAY as in RFC 2119. Uses two catalogued devices
(`../../_terms.md`): [device::IncidenceMatrixPair](../../_terms.md#deviceincidencematrixpair),
[device::LogGrowthChart](../../_terms.md#deviceloggrowthchart).

## Scope
**In scope:** `memory-bank/visualizations/A100001/viz.html` — the Fano-plane picture, the matrix/transpose
comparison, the growth chart, and their numeric content — plus the `solution.mjs` / `proof.mjs`
pair that computes and checks the sequence itself.

**Out of scope:** the devices' own quality requirements (`../../specs/approaches.md`,
`../../specs/visualizations.md`); the repository-wide page-structure rules.

## Architecture

### Overview (prose)
The page opens with the Fano plane — the unique `(7_3)` configuration and the smallest self-dual
one — drawn as the classic triangle + 3 medians + incircle, with hover highlighting the 3 lines
through a point. It then shows the configuration's 7×7 incidence matrix next to its transpose
([device::IncidenceMatrixPair](../../_terms.md#deviceincidencematrixpair)), deliberately not
relabeled to look alike, captioned with the true (weaker) claim that a relabeling exists rather
than the false (stronger) claim that the two grids already match. A
[device::LogGrowthChart](../../_terms.md#deviceloggrowthchart) closes the page with `a(n)` for
`n=1..19`, marking `n=7` as the first nonzero term.

### Code
`sequences/A100001/solution.mjs` builds every `(n_3)` configuration up to isomorphism — lines are
added through the smallest point that still needs one, point 0's three lines are fixed in advance
and never-used points take the smallest free label, so the search produces a few labellings per
configuration instead of every relabelling — then swaps points and lines in each one and counts the
configurations isomorphic to that swap. `sequences/A100001/proof.mjs` re-checks all of it with its
own routines: a plain permutation search with no invariant colouring, the Fano plane rebuilt from
algebra rather than from a search, the independently published count of all `(n_3)` configurations
(A001403) as the completeness reference, and — for every configuration called self-dual — explicit
point and line permutations verified cell by cell against the raw incidence matrix, which is the
same claim the page's matrix-and-transpose picture makes visually.

### Data
- The page embeds `a(1)..a(19)` directly in its `<script>`, used both for the growth chart and the
  Fano-plane example's own hover tooltip values.
- `solution.mjs` embeds nothing; `proof.mjs` embeds the published terms of A100001 and A001403,
  which is its job.

## Requirements
> Statement — acceptance criterion — status.

### MUST
- The page's embedded values MUST match OEIS's own data for `A100001` exactly —
  **MUST-match-oeis-data** — criterion: every `n=<k>: <v>` tooltip value in
  `memory-bank/visualizations/A100001/viz.html` equals the corresponding term of OEIS's `%S` line. Status: done —
  re-fetched live 2026-09-01 from `oeis.org/search?q=id:A100001&fmt=text` (`%S A100001
  0,0,0,0,0,0,1,1,3,10,25,95,366,1433,5802,24105,102479,445577,1992044`, `%O A100001 1,9`); diffed
  term-by-term against the page's 19 embedded values — exact match, zero differences.
- The incidence matrix and its transpose MUST be drawn from the SAME concrete Fano-plane labeling
  used in the point-and-line diagram above them (not a separately chosen, more symmetric-looking
  labeling) — **MUST-matrix-matches-diagram** — criterion: the matrix's 7 rows/columns correspond,
  in order, to the same 7 points and 7 lines drawn in the diagram, with no relabeling applied for
  presentation. Status: done.
- The page MUST be a single self-contained HTML file — **MUST-self-contained** — criterion: opens
  correctly via `file://`, no dependency beyond the Google Fonts stylesheet link. Status: done.
- `sequences/A100001/solution.mjs` MUST compute `a(n)` from the definition, consulting no table of
  known answers — **MUST-implementation-present** — criterion: the file contains no array of
  published terms that any computation reads from, and running it reproduces the sequence.
  Status: done — `node sequences/A100001/solution.mjs 12` run live, output
  `0, 0, 0, 0, 0, 0, 1, 1, 3, 10, 25, 95`, the last term taking ~15 s; `n=13` run separately gave
  2036 configurations and 366 self-dual in ~4 minutes, both matching the published terms.
- `sequences/A100001/proof.mjs` MUST re-check that output with routines written independently of
  the search that produced it, covering soundness, distinctness, completeness, duality witnesses
  and agreement — **MUST-proof-independent** — criterion: `node sequences/A100001/proof.mjs 12`
  exits 0, and its isomorphism test is its own plain permutation search rather than the pruned one
  imported from `solution.mjs`. Status: done — run live, 71 s, output ends `All checks passed for
  n = 1..12: sound, distinct, complete, witnessed, and equal to OEIS A100001.`; at `n=12` all 229
  configurations were revalidated and all 95 self-duality claims carried a witness verified cell by
  cell on the incidence matrix, and at `n=7` the algebraically-built Fano plane matched exactly one
  returned configuration.
- Each `(n_3)` configuration count MUST agree with the independently published count of ALL such
  configurations, not only with the self-dual subcount — **MUST-total-count-agrees** — criterion:
  the number of configurations the search returns equals OEIS A001403's term for that `n`.
  Status: done — `1, 1, 3, 10, 31, 229` returned for `n = 7..12` and `2036` for `n = 13`, matching
  A001403 exactly; without this the self-dual count could come out right while the enumeration
  underneath was wrong.
- `sequences/A100001/solution.mjs`'s header MUST state the measured range and where the search
  stops, from runs that were executed — **MUST-runtime-honest** — criterion: the header names the
  largest `n` that finishes with its time and where it stops. Status: done — measured: `n ≤ 10`
  under 0.1 s, `n = 11` about 0.9 s, `n = 12` about 15 s, `n = 13` about 4 minutes; the header says
  `n = 14` was not run rather than guessing at it, and states that the published terms run to
  `n = 19` where no search of this shape gets.
