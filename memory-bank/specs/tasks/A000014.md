# A000014 — series-reduced trees with n nodes

## Vision
`a(n)` counts unlabeled trees on `n` nodes where no vertex has degree exactly 2 — every vertex is a
leaf (degree 1), an isolated single node (degree 0, only at `n=1`), or a branch point (degree 3+).
The naive question ("how many trees on `n` nodes look like this?") gives no handle on why `a(3)=0`
even though a tree on 3 nodes obviously exists. The page's central claim: any vertex of degree 2 can
always be erased, merging its two incident edges into one, without changing which tree it fundamentally
is (the two graphs are homeomorphic) — so a candidate that fails the rule was never a genuinely new
shape, only an already-counted smaller one with a redundant stop added to it.

## Architecture

### Overview (prose)
`memory-bank/visualizations/A000014/viz.html` runs Problem (a 3-node tree that obviously exists,
yet `a(3)=0`) → (1: the only two allowed vertex kinds — leaf, branch point — with every vertex
labelled by its own printed degree) → (2: the punchline, via
[device::DegreeTwoCollapse](../../_terms.md#devicedegreetwocollapse) — the disqualifying vertex
erased, its two edges merged, landing exactly on the already-counted 2-node tree) → (3: the two
6-node shapes, showing the same rule holds at a slightly richer scale, with every vertex still a
leaf or a branch point) → Solution (the verified growth chart through `n=20`, via
[device::LogGrowthChart](../../_terms.md#deviceloggrowthchart)).

### Code
`sequences/A000014/solution.mjs` computes `a(n)` by leaf-addition growth: starting from the
single-node tree, every unlabeled tree of size `k+1` is reached by attaching a new leaf to every
vertex of every already-found unlabeled tree of size `k`, deduplicating by a canonical form (center
+ AHU string) at each step; the degree-2 filter is applied only to the final size-`n` trees.
`sequences/A000014/proof.mjs` does not reuse that construction: it independently decodes every one
of the `n^(n-2)` labeled trees on `n` nodes from its Prüfer sequence — an unrelated, exponential
construction with no leaf-addition and no relabelling-free growth — filters and canonicalizes each
with its own from-scratch centering/AHU routine, and compares the resulting count to the fast
method's output; separately, the fast method's own output is checked directly against OEIS's
published terms over a wider range than the exponential construction can reach.
