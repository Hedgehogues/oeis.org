# A000026 — mosaic numbers

## Vision
If `n = ∏ p_j^k_j`, `a(n) = ∏ (p_j · k_j)`. The per-term rule is a one-line restatement of prime
factorization with no further "why" on its own. What the page demonstrates instead: OEIS's own
comment states `a(n) = n` whenever `n` is squarefree — true, and checkable directly (every exponent
is 1, so every factor `p·1 = p` reproduces `n` unchanged) — but that comment is a one-directional
`if`, not an `iff`, and checking the converse directly (rather than trusting the comment's informal
phrasing) finds a real counterexample: `n = 4 = 2²` is not squarefree, yet `a(4) = 2×2 = 4` anyway,
an incidental fixed point where an exponent happens to equal its own prime. The page's central
claim is exactly this distinction — squarefree implies fixed, always; fixed does not imply
squarefree.

## Terms
MUST/MUST NOT/SHALL/SHOULD/SHOULD NOT/MAY as in RFC 2119. Uses no catalogued device: the page's two
worked examples (`6 = 2×3`, `4 = 2²`) are plain factorization chips, not a reusable diagram
convention distinct from what other simple pages already render without a formal
`[device::*]` record.

## Scope
**In scope:** `memory-bank/visualizations/A000026/viz.html` — the current, only page for this
sequence (no kept drafts) — and the `solution.mjs`/`proof.mjs` pair.

**Out of scope:** any claim about HOW OFTEN incidental fixed points occur asymptotically (checked
only empirically, for `n` up to 5000, not proven or claimed to follow a closed form).

## Architecture

### Overview (prose)
`memory-bank/visualizations/A000026/viz.html` runs Problem (`a(n)` for `n=1..12`, some landing back
on `n`) → (1: squarefree `n` always works, worked on `6 = 2×3`) → (2: but it's not the only way —
`4 = 2²` also lands back on `4`, incidentally) → Solution (squarefree implies fixed, always; the
converse is false, `4` a real counterexample rather than a caveat glossed over).

### Code
`sequences/A000026/solution.mjs` factorizes `n` by trial division and multiplies each prime by its
own exponent. `sequences/A000026/proof.mjs` does not reuse that factorization: it builds a
smallest-prime-factor sieve independently and factorizes through that instead, then separately
checks the ACTUAL direction of OEIS's own fixed-point comment (squarefree ⟹ fixed) rather than the
stronger, unstated converse a first version of this check assumed and which failed immediately at
`n=4`.
