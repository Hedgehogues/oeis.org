OEIS · A000002

The self-describing sequence

? Problem

A sequence of only 1s and 2s, starting a(1) = 1. What rule decides every next term?

?
↓

1 What's a run?

1a

The first 9 terms, one cell each.

1b

A run is a maximal stretch of equal neighbours. Group the same 9 cells into runs, one merged box per run, and read off each box's length.

1c

2 Compare that row to where we started

2a

Line the 6 run lengths from step 1 up against the sequence's own first 6 terms, position by position.

Every position matches. The row of run lengths is the sequence again — A000002 is its own run-length encoding: a fixed point of that transform, not just a string that happens to start this way.

↓

3 Build it from that one rule

Getting started (forced, not chosen): a(1)=1 by definition, so run 1 is just [1]. Run 2's colour is forced to flip to "2" regardless of its length — so term 2 is a "2" no matter what, which pins a(2)=2: run 2 has length 2, giving [2,2]. That's 3 terms down before any self-reading starts.
3a–3d

From here on, every next run's length is a term the sequence already wrote earlier — read it, append that many cells in the flipped colour (new), move on.
